## 作業中: 難易度の調整

ユーザーの方針: 「日ごとの片付けの代わりにショップの価格を引き上げてよい」。調整は `pnpm balance` のレポートを根拠にし、docs/balance-log.md に記録する。

### やったこと

- ボットが「今日の出来事」を選ぶとき、候補ごとにその朝の手を考えて見込み（出荷量 ÷ ノルマ）が最も良いものを選ぶようにした（tools/balance/src/runner.ts の `chooseBestEvent`）
- 現状の計測（seeds 1〜200・初期解放・評価は平均）:

| ボット | 全シフトクリア率 | 1シフト目のクリア率 |
| ------ | ---------------- | ------------------- |
| greedy | 27%              | 90%                 |
| mid    | 20%              | 89%                 |

- 片付け導入前（SIM_VERSION 2）は greedy 23%・mid 21% で、全体のクリア率はほぼ変わっていない
- 1シフト目（ノルマ 3）で約1割が出荷量 0 で脱落している。以前の分析ではポンコツロボの期待値を過大評価しているのが原因の見立て
- 2日目の朝（片付け直後・シフト4）のクリア率が他より少し落ちる
- 使われていないパーツ（購入率ほぼ 0）: 合流炉・連鎖メーター・コピー機・回転台・潤滑油タンク・検品台・貯金箱（初期解放では並ばないため。解放条件を引き上げた影響もある）

### 次にやること

1. `pnpm balance --seeds 200 --bots greedy,mid --eval worst --samples 5` で「慎重なプレイヤー」の数値も取り、ボットの判断の甘さとゲームの難しさを切り分ける（実行途中で止めたので未計測）

## 作業環境のメモ

- ブラウザでの確認は `vite build --outDir /tmp/...` → `vite preview --port 5199` → Playwright（`/opt/node22/lib/node_modules/playwright/index.mjs`）。開発サーバー（`pnpm dev`）は Playwright からだと 504 になることがある
