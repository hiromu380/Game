## 4. フェーズ4（Steam 化）で決めるべき論点（案）

ロードマップ: Electron 化・実績・クラウドセーブ・Steam ページ・Next Fest

### A. Electron 化

- `apps/desktop` を新設。steamworks.js は**着手時に保守状況を再確認**（CLAUDE.md の指示）。代替候補の比較も
- Web 版との違いへの対応
  - ページの配信元が `file://`（またはカスタムプロトコル）になる → `_headers`（CSP）が効かない。Electron 側で CSP を設定する
  - Service Worker（PWA）は不要。無効化する
  - API の接続先を絶対 URL にする（`VITE_API_BASE`）。サーバーの CORS 許可（`CORS_ORIGINS`）の扱い
  - 同梱フォント・PixiJS（`pixi.js/unsafe-eval` 読み込み済み）は動く想定だが要確認
- 製品版ビルド（`VITE_EDITION` 既定 = full）。体験版との出し分け
- 自動更新は Steam に任せる前提か

### B. ID の引き継ぎ・Steam 連携

- 現在の匿名 ID は端末保存のみで、消えると別人扱い
- Steam 版は Steam のユーザー認証（認証チケットをサーバーで Steam Web API に照会）で ID を発行・紐づけるか
- Steam ユーザーは Turnstile を省略できるか（Electron で Turnstile はホスト名の制約があり動かない可能性）
- Web 版の匿名 ID から Steam 版へ記録を移す手段を作るか（要相談）
- サーバー側は adapters／domain の分離を守る（Steam 固有の処理はアダプター層）

### C. クラウドセーブ

- Steam Cloud（ファイル同期）で済ませるか、自前サーバーに保存するか
- セーブデータは `SAVE_VERSION` 付き（現在 2）。ユーザー設定は別保存
- 競合時の扱い（どちらを優先するか）

### D. 実績

- メタ進行の記録（`MetaRecords`: 累計出荷量・到達シフト・最大連鎖・1シフト最大出荷量・ラン回数・全クリア回数）と解放条件をそのまま使える
- 実績の一覧と条件は数値なので balance.ts か設定ファイルに置く
- 延長戦・デイリー関連の実績を入れるか

### E. Steam ページ・Next Fest

- ストアページの素材（カプセル画像・スクリーンショット・トレーラー）は本番イラスト待ち
- Next Fest 用デモ: 体験版の設定（初期パーツ・7×7・延長戦なし）を流用できる
- 体験版の「製品版への誘導」（`VITE_STORE_URL`）に Steam のストア URL を入れる

### F. フェーズ3の持ち越し

- 本番デプロイと Web 体験版の公開（人が実行）
- バランスの再開（上記）
- 規約類の確定、Steam 版向けの規約・プライバシーポリシーの追記（Steam の ID を扱う場合）
