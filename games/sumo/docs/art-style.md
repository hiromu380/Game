# 絵柄の決まり（一門）

絵（部屋の箱庭・顔の絵・表紙・取組の土俵）はドット絵でそろえる（2026-11-11。下の「ドット絵」）。A案「ゆるい浮世絵を立体化」の3D（`art/three/`）と平面のSVG（`art/BoutStage.tsx`・`art/Figure.tsx`）は、いまは画面から使っていない（コードは残してある。下の「取組」以降はその3Dの決まり）。二〜二・五頭身、墨の輪郭、落ち着いた和色、少ない段階の陰影で統一する。生成AIの参考画像は方向性の確認だけに用い、ゲームの素材には使用しない。

## 造形と色

- 取組の力士・行司・土俵はコード製の3D。経営画面は文字を中心とする和紙・罫線。全面の反復模様を避け、藍の帯と朱の印、細い罫線で階層を作る。画像テクスチャ、金属的な反射、被写界深度、写真風の影は使用しない。
- 色は `client/src/art/palette.ts` に集約し、UIはそこから配るCSS変数を使う。
- 輪郭は背面の墨色の面。部品の大きさに対して単純に拡大せず、一定の厚みを加える。胸と腹、表情にだけ細い線を置く。
- 陰影は三段のトゥーン。胴は胸から腹へ連続する回転体で造形し、腕・親指・帯の折り返し・結った鬢に必要な線だけを加える。静的な面は支点と色ごとに結合する。球・箱・押出しのインデックス形式を揃え、統合時に形状を欠落させない。
- 土俵は四角い台と円形の勝負俵。俵は28束を円周の接線方向に並べる。吊り屋根は反りのある押出し形状、水引幕はたるみのある紫、房は白と朱。俵には二本の結束縄を置き、遠景は二色の山並みとして描く。実寸の再現より画面での読み取りを優先する。

## 人物の同一性と状態

- 既存の `Look` をドット絵・SVG・3Dで共有する。力士ID由来の目・眉・口・肌色を保つ。顔の組合せと輪郭、体重による胴幅で個体差を示す。
- ざんばら、ちょんまげ、大銀杏を輪郭で区別する。大銀杏は頭の上で前へ折り返し、葉先の切れ込みと放射状の筋を持つ。冠のように直立させない。
- 関取は部屋色の締め込みと下がり、横綱は白い綱。けがは包帯、疲労は汗。親方には袖・裾・合わせ襟・帯・紋を付け、年齢で髪色を変える。
- 顔の絵（弟子・入門希望者・親方・歴代力士・見せ場）はコードで描くドット絵（下の「ドット絵」）。取組は `figure3d.ts` の3Dモデル。

## ドット絵（箱庭・顔の絵・表紙）

- 部屋の箱庭の建物と小物は取り込んだスプライト、人と顔の絵はコードで1ドットずつ組み立てる（`client/src/art/pixel/`・`art/hakoniwa/people.ts`）。色は palette.ts、輪郭は墨、陰は右下に1段。
- 顔の絵（`art/pixel/portrait.ts`）: 正面を向いた、番付の顔写真のような構図。胸像 40×40・全身 48×62 ドット。
  目（4種）・眉（3種）・口（4種）・肌（3色）は ID から、髪（ざんばら・ちょんまげ・大銀杏・短髪・白髪）・体の幅・まわしの色・下がり・横綱の綱・ばんそうこう・汗は今の状態から決まる（`Look`）。
- 画像にするときは整数倍（6倍）に拡大し、表示の大きさへはブラウザに縮めさせる（半端な倍率でもドットの大きさがそろう）。同じ見た目は1回だけ画像にして使い回す。
- 取組の舞台（`playback/boutStage.ts`・`ui/BoutStagePixel.tsx`）: 184×170 ドットの1枚のキャンバス。暗い客席（コードで描く）・土俵と吊り屋根（取り込んだ絵。屋根は軒と房だけ見せる）・行司・2人の力士（箱庭の人と同じ絵。関取は締め込みの色）。
  台本の姿勢（位置・傾き・組んでいるか）から、仕切り・押し合い（2コマ）・倒れる（足元を軸に傾ける）・勝ち名乗りを選ぶ。当たった瞬間の火花と揺れ・土けむりは、動きを減らす設定では出さない。
- 箱庭の人と物の前後: 人の足元のマスが、物の手前の辺より手前にあれば物の後に、奥にあれば物の前に描く（`grid.ts` の depthAmong）。門や幟の奥にいる人は隠れる。

## 取組

- 勝敗・決まり手・台本の時刻は従来どおり。`sim/` と `playback/boutScript.ts` は変更しない。
- 東は右、西は左。人物の向きだけを内側へ向け、倒れの支点は世界の左右に保つ。すり足・腰落とし・押し手は描画の補間だけで加える。
- 2Dの点を立体へ写した際の胴の貫通は、表示上の間隔と着地点で補正する。これは物理演算や勝敗判定ではない。
- 倒れたモデルの実頂点を使って最低点を土俵面へ合わせる。焼き込んだ形状の重複頂点を一度だけ除き、測定結果を接地・画角で共有する。描画しないフレームでは測定も省く。行司は奥に置く。画角を人物の外形に合わせ、土俵外へ出た頭まで収める。
- 初回ロードと描画器の準備が済んでから演出時計を始める。動きを減らす設定では最終場面のみ。背景タブ復帰時は現在の姿勢を再描画する。

## 取組の3Dの性能・復旧

- Three.jsは動的インポート。取組を見るときにだけ3Dチャンクを取得する（表紙と顔の絵は3Dを使わない）。
- タッチ端末はDPR上限1.3・描画目標上限30fps、その他は1.5・45fps。面積の予算も設ける。これらは実機での速度保証ではない。
- 取組を閉じたらジオメトリ・材質・トゥーン用テクスチャ・レンダラ・コンテキストを解放する。React StrictModeの再初期化時は新しいCanvasを使う。
- WebGL利用不可、描画失敗、コンテキスト喪失、3Dファイルの読み込み失敗は既存SVGへ戻す。

## 経営画面

- 表紙は架空の三輪の紋と朱印、額に入れた春の部屋の箱庭（ゲームの中と同じ絵・同じ描き方で、弟子が動く。`client/src/ui/TitleScene.tsx`）。
- 番付は墨の罫線と朱の印。広い日本語画面だけ四股名を縦書きにし、スマホ・英語では横書きにする。
- 帳簿は和帳の綴じと罫線、等幅の数字。系譜は掛け軸の木軸と接続線。師匠・分家・待機・閉鎖は文字と枠も併用する。
- 弟子カードは白い紙面と上部が丸い肖像枠。PCでは二列、スマホでは一列に並べる。名前・能力・稽古方針の順に読み取れる余白を置く。左側を塗り分ける帯を設けない。長い名前は折り返す。
- Kaisei Tokuminの本文用Regular（400）と見出し用ExtraBold（800）のサブセットを同梱し、環境による太さの差を抑える。追加文言は日英i18nで管理し、フォントのサブセットを再生成する。
- 本文コントラスト比4.5:1以上。操作領域44px以上。意味は装飾画像だけに持たせず、状態は文字・記号でも示す。

## 確認方法

既存SVGのSSR一覧は `client/build/gallery.tsx`、3Dの造形一覧は開発時の `/build/review.html`。主要画面・形状・描画速度・20回開閉・SVG復旧は `client/build/verify-graphics.mjs` で再検証できる。詳しい実行方法と実測条件は `graphics-validation.md` を参照する。
