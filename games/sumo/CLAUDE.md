# CLAUDE.md — 一門（仮）

相撲部屋の経営シミュレーション。`games/sumo/` 以下の設計書。作業前に必ず読み、ここに反する実装をしないこと。
仕様の変更が必要だと判断した場合は、実装する前に提案して承認を得ること。
リポジトリ直下の CLAUDE.md は別のゲーム（Chain Factory）の設計書。コードは共有しない（実装ルールの考え方だけ同じにする）。

---

## 1. ゲーム概要

- ジャンル: 相撲部屋の経営シミュレーション × 世代をまたぐローグライト
- コンセプト: 親方として弟子を育て、引退した弟子が親方になって次の代を継ぐ。代を重ねるほど「一門」の系譜図が広がり、
  受け継いだ家訓と型で、いつか横綱を出す
- 核の仕組み: **一門の系譜**。1人の親方の任期が1代。代の終わりに、育てた関取の中から跡継ぎを選んで次の代へ進む。
  跡継ぎがいなければ一門は断絶（ゲームオーバー）
- 遊ぶ環境: Web（PC・スマホ両対応）。1代 20〜30分、一門の断絶か目標達成まで続く
- 世界観・トーン: 架空の相撲界。実在の力士・部屋・団体の名前は使わない。少しとぼけた、乾いたユーモア
- 仮素材（単純図形と文字）で開発し、あとで絵に差し替えられるようにする

## 2. コアループ

1代 = 親方の任期（`balance` の `termBasho`。仮: 30場所 = 5年）。1年は6場所。

1. 場所前（稽古の期間）
   - 弟子ごとに稽古の方針を1つ選ぶ（押し・四つ・技・体づくり・休養）。伸び方は年齢・素質・疲労・親方の得意で決まる
   - 時々、新弟子の候補が来る（スカウト。お金がかかる。素質は一部しか見えない）
2. 本場所（15日。幕下以下は7番）
   - 取組は自動のシミュレーション。結果の一覧と、見どころの数番だけを短く見せる
3. 番付発表
   - 勝ち越し・負け越しの大きさで番付が上下する。大関で2場所続けて好成績なら横綱へ
   - 収入（部屋への補助・関取の給金・懸賞）と支出（弟子の生活費）を精算する
4. 年の終わり
   - 弟子は1歳年をとる。衰えた弟子・番付の下がった年長の弟子は引退する（本人が言い出す）
5. 代の終わり（任期の最後の場所の後）
   - 跡継ぎを選ぶ: 十両以上に上がったことのある弟子（現役なら引退して継ぐ）
   - 選んだ弟子が新しい親方になり、次の代が始まる。部屋の弟子の一部は残る
   - 跡継ぎの候補がいなければ一門は断絶し、ゲームが終わる（それまでの系譜図と記録が残る）

### 受け継ぐもの（世代をまたぐ仕組み）

- **型**: 親方の得意な型（押し・四つ・技）の稽古は、その部屋の弟子がよく伸びる
- **家訓**: 代の終わりに、その代の出来事から候補が出て1つ書き加える（例: 大関を出した →「立ち合いは当たれ」押しの伸び＋）。
  枠に上限があり、いっぱいなら1つ書き換える。家訓は一門のすべての代に効く（ローグライトの「ビルド」にあたる）
- **四股名の一字**: 弟子の四股名には親方の四股名の一字が入る（自動の名づけ）。系譜図で血筋が見える
- **名声**: 関取・三役・横綱を出すたびに一門の名声が上がり、スカウトに来る新弟子の素質が上がる

### 終わりと目標

- 断絶でゲームオーバー。結果は「何代続いたか・横綱を何人出したか・名声」
- 系譜図（親方 → 弟子 → 孫弟子…）は、ゲームが終わっても記録として残り、画像で共有できる（後のフェーズ）

## 3. シミュレーション仕様

### 原則

- **完全決定論**: 同じ入力（状態・シード）なら必ず同じ結果。乱数はシード付き PRNG だけ。`Math.random()`・`Date` を使わない
- シミュレーションは純粋関数。描画・DOM・保存に依存しない
- 数値（伸び方・勝率の係数・番付の動き・お金）は `sim/src/balance/` に集める。コードに直書きしない
- 乱数のシードは、ゲームのシードから用途ごとに派生させる（稽古・取組・スカウト・引退・家訓の候補）

### 力士

- 能力: 押し・四つ・技（それぞれ 0〜100）、体重、気力（調子。場所ごとに変わる）
- 隠れた値: 素質（伸びの上限と速さ）、ピークの年齢
- 型: 3つの能力のうち一番高いもの
- 疲労とけが: 稽古で疲労がたまる。疲労が高いとけがをしやすい。けがの間は休場（不戦敗）

### 取組

- 強さ = 能力（型の相性を加味）＋ 体重差の補正 ＋ 気力
- 型の相性（三すくみ）: 押し > 技 > 四つ > 押し。相性の良い側に補正
- 勝つ確率は強さの差から決め（ロジスティック関数）、シード付き乱数で勝敗を決める
- 決まり手は型と勝ち方から選ぶ（見せるための情報。勝敗には影響しない）

### 番付

- 地位: 序ノ口・序二段・三段目・幕下・十両・前頭・小結・関脇・大関・横綱
- 番付は「地位の中の枚数」まで持つ。勝ち越し・負け越しの数で枚数が動く
- 相手は同じ地位あたりの架空の力士（その場で作る。強さは地位から決まり、ばらつく）
- 大関は2場所続けて負け越すと陥落。横綱は陥落しない（成績が悪いと引退する）

### お金

- 収入: 部屋への補助（弟子1人あたり）・関取の給金・懸賞（幕内の勝ち星）
- 支出: 弟子の生活費（1人あたり）・スカウト
- 所持金がマイナスで場所を終えると、弟子を1人手放す（後のフェーズで調整）

## 4. 技術構成

- TypeScript（strict）・pnpm workspaces（リポジトリのワークスペースに `games/sumo/*` を足す）・Vitest
- クライアント: Vite + React（盤面のような絵が要る所は Canvas）

```
/games/sumo/sim      純粋なシミュレーション・ルール・バランス定数（依存ゼロ）  @ichimon/sim
/games/sumo/client   Web クライアント（Vite + React）                        @ichimon/client
```

## 5. 実装ルール

- 文言は i18n ファイル（`client/src/i18n/ja.json`・`en.json`）に置く。既定は日本語
- `sim` は必ずテストを書く（決定論・各ルールの挙動・終わること）
- セーブデータはバージョン番号を持たせ、上げたら変換とテストを足す
- 状態は色だけで伝えない。本文のコントラスト比 4.5:1 以上、スマホの操作領域は 44px 以上
- バランスの調整は自動プレイの結果を根拠に行い、記録する
- 大きな変更の前には計画を示してから着手する

## 6. ロードマップ

1. **MVP**: 1代を最後まで遊べる（稽古の方針・本場所の自動進行・番付・お金・引退・跡継ぎ選び・次の代）。家訓は数種、仮素材
2. **系譜**: 系譜図の画面・家訓を増やす・四股名の一字・名声とスカウト・セーブ
3. **見せ方**: 取組の短い演出・場所のハイライト・音
4. **広げる**: ライバル部屋・一門どうしの交流・共有（系譜図の画像）
